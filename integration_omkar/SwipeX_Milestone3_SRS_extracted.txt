1. Introduction
1.1 Purpose
This Software Requirements Specification (SRS) defines the scope, tasks, responsibilities, dependencies, and
integration requirements for Milestone 3 of the SwipeX platform. It builds directly on the Milestone 1 and Milestone 2
increments — working Authentication/RBAC, the finalized database schema, the live Job/Swipe/Search/Company
services, and the heuristic ATS and Matching Engine stubs — and translates the project charter's AI Resume Analyzer
& ATS Scoring and Personalized Job Recommendation System modules into a coordinated, day-wise execution plan
for five interns working in parallel, so that their individual deliverables converge into a single, functioning system
increment by the end of Day 7.
1.2 Scope of Milestone 3
Milestone 3 covers AI Resume Analysis & Recommendations. By the end of Day 7 the team must deliver a working
increment consisting of: a Resume Service supporting resume upload, storage, and multiple versions; a text-
extraction and skill-extraction pipeline that parses uploaded resumes (PDF/DOCX); a real ATS Scoring engine that
blends keyword-match percentage with semantic similarity to compute a resume-job compatibility score, and that
identifies missing skills and missing keywords when the score falls below the 80% threshold defined in the project
charter; an AI-generated resume-optimization-suggestions module; an upgraded Recommendation/Matching Engine
that replaces the Milestone 2 heuristic with semantic-similarity- and ATS-aware scoring; and a connected frontend
that lets a Job Seeker upload a resume, see their ATS score with missing skills/keywords highlighted, read AI-
generated suggestions, and see AI match percentages on recommended jobs — all validated inside the shared
local/dev Docker Compose environment.

1.3 Definitions & Abbreviations
• SRS — Software Requirements Specification
• RBAC — Role-Based Access Control
• JWT — JSON Web Token, used for stateless authentication
• API Gateway — Single entry point that routes requests to backend services
• ATS Score — The percentage compatibility between a resume and a job, blending keyword match and semantic
similarity
• Skill Extraction / NER — Named-Entity Recognition used to pull skills, roles, and experience out of raw resume
text
• Semantic Similarity — A vector-embedding-based measure of how closely resume content matches a job
description in meaning, not just exact keywords
• Vector Database — A database (e.g., ChromaDB) that stores text embeddings and supports similarity search, used
here for resume-job semantic matching
• LLM — Large Language Model, used in this milestone to generate human-readable resume-optimization
suggestions
• M1–M4 — Milestone 1 through Milestone 4, as defined in the project charter
• Intern 1–5 — Shorthand for the five domain owners defined in Section 4

1.5 Golden Rule for This Milestone
Every tool used in Milestone 3 must be free. Text extraction, skill/keyword extraction, embeddings, and the vector
database are all done with free, open-source libraries. Where the project charter names OpenAI API for the LLM
Service, the team treats this as optional: if free trial credits are available they may be used for the AI-suggestions
feature, but the module must degrade gracefully to a fully free, rule-based suggestion generator so that no paid
subscription is ever required to complete or demo this milestone.

3. Overall Introduction
Milestone 3 fills in the AI/NLP Services layer of the project charter's architecture diagram — Text Extraction &
Preprocessing, Skill Extraction (NLP), Keyword & ATS Analysis, Semantic Similarity & Matching, and an LLM Service for
suggestion generation — alongside the Resume Service and ATS Scoring Service on the backend side, and the Vector
Database in the Database & Storage layer. Where Milestone 1 shipped a heuristic ATS stub and Milestone 2 shipped a
rule-based Matching Engine so the rest of the team could integrate early, Milestone 3 replaces both with the real
implementations: actual resume parsing, actual keyword-and-semantic ATS scoring, actual missing-skill/keyword
detection, actual AI-generated improvement suggestions, and a Recommendation Engine that blends semantic
similarity with the Milestone 2 swipe-history signal.

5. Milestone 3 Objectives
• Extend the database schema to support resumes, resume versions, extracted skills, and job required-
skills/keywords.
• Implement the Resume Service: upload, storage, versioning, and retrieval of resumes.
• Implement a text-extraction and NLP skill-extraction pipeline that parses uploaded resumes into structured,
queryable data.
• Implement the ATS Scoring engine: a blended keyword-match and semantic-similarity score between a resume
and a job, with missing-skill and missing-keyword detection when the score is below 80%.
• Implement an AI-generated resume-optimization-suggestions module, with a fully free fallback if no LLM
budget/credits are available.
• Upgrade the Recommendation/Matching Engine to use semantic similarity (via a free, open-source vector
database) blended with the Milestone 2 swipe-history signal.
• Deliver a connected frontend: resume upload with version management, an ATS score dashboard with missing
skills/keywords highlighted, an AI-suggestions panel, and AI match percentages surfaced on recommended jobs.
• Validate the full increment through integration testing, automated checks (with AI/vector calls mocked for
determinism and cost control), and a defect-tracked QA cycle — without production deployment.

13. Milestone 3 Acceptance Criteria
• Job Seekers can upload a resume, retrieve prior versions, and see it correctly parsed into structured
skills/experience.
• The ATS Scoring engine returns a blended keyword-and-semantic-similarity score for any resume/job pair.
• When the ATS score is below 80%, the system correctly identifies and returns missing skills and missing keywords,
per the project charter's example.
• The AI-suggestions module returns resume-optimization suggestions, with a working free fallback when no LLM
credits are available.
• The Recommendation/Matching Engine is upgraded to use semantic similarity blended with Milestone 2's swipe-
history signal, and is reachable end-to-end through the Gateway.
• The frontend supports resume upload/versioning, displays the ATS score with missing skills/keywords, shows AI-
generated suggestions, and surfaces AI match percentages on job cards.
• RBAC restricts resume upload, ATS scoring, and suggestion actions to the Job Seeker role.
• All Milestone 3 services run together and pass integration/smoke tests inside the local Docker Compose
environment.
• CI enforces lint, build, and automated test checks on every pull request, with AI/vector-DB calls mocked for
determinism and cost control.
• Every tool used across the milestone was free/open-source — no paid subscriptions were required.
• No production deployment activity has occurred; deployment remains explicitly scheduled for after Milestone 4.
